# Local collaboration interface

Operate mode. Preserve the existing green accent, pale neutral background and Windows system typography. Replace the dense permanent form/evidence wall with a project history sidebar, a concise setup surface, explicit stage assignments and a current-task workspace. Primary actions describe the next safe action. Technical files live in progressive disclosures. Use visible labels, 44px controls, keyboard focus and responsive stacking at narrow widths. Real dispatch history is authoritative; planned assignments never masquerade as executed work.

The current assignment surface uses frontend/backend work-mode controls and separate rows for tool, native model and reasoning effort. Planning defaults to Codex; review stays on Codex with a fresh session. Rows stack their labeled controls on phones. Optional domain path restrictions remain collapsed. Catalog failures and unsupported saved options remain visible, and refreshing models preserves the user's draft. Actual execution names the domain and concrete model/effort, distinct from future assignments.

The task workspace uses separate Conversation, Execution and Results tabs beneath a compact status summary. Keep the composer docked below the independently scrolling tab content, including while execution or results are selected. Preserve each task's selected tab, tab scroll positions and conversation draft through polling and navigation. Timestamped execution rows separate preparation, tools, output, public model messages and reasoning status. Details disclose long output; filtering and explicit follow controls support reading without forced scrolling. An explicit read-only choice near project entry bypasses copy preparation and exposes the investigation assignment alone.

The Conversation tab retains actual project messages and source-based replies with expandable facts, unknowns and citations. Use a short task title; disclose the complete goal and appended batch requirements in the conversation without rewriting stored requirements. Keep the composer stable while task polling updates message delivery. Offer explicit read-only questions and modification requirements, explaining safe-boundary delivery and the current batch's round budget. Preserve per-task drafts on navigation, reload and send failures, and never clear another task's draft on delayed completion. A completed inspection or accepted batch can start a linked next batch in the same directory with one explicit send action.

Results distinguish the current batch's verification from completion of the whole project. Surface unresolved review findings, the recorded round and source fingerprint before the original evidence links. Each check opens its own recorded log; patch and review links follow the actual evidence inventory. Retain raw evidence and handoff history behind disclosures. This presentation does not create an implementation summary, readable per-file diff or running website preview when those artifacts do not exist.

Keep the avatar, configurable background and existing theme tokens. Existing tasks default to a wider working surface, with a local width toggle that can reserve the right-hand portrait area again. New-task setup preserves its portrait layout. Width and tab changes affect presentation only and never change native assignments, task history or evidence. At phone width, keep tabs, status, composer and Agent settings reachable without horizontal page scrolling.

Move native assignment controls into a right-side Agent settings drawer. Persistent sidebar/header toggles open and close it; role tabs expose one full-width tool/model/reasoning group at a time. Keep desktop conversation usable beside the panel and use modal focus containment on narrower screens. Preserve unsaved selections and expose an unsaved marker when collapsed. Completed tasks edit future preferences; execution records and candidate acceptance evidence retain their original selections.
